# 第 28 轮：详情返回原模型入口的焦点恢复

**本轮仅修改代码并静态审阅。未编译，未执行测试、脚本或应用。React renderer、真实浏览器 DOM、Windows/WebView2 原生键盘焦点、NVDA 与 Narrator 均未测试。以下全部为维护者待执行的回归步骤，不是通过记录。**

## 改动边界

- 首页仍是一行一个原生 `button`，不添加嵌套按钮，不拦截 Enter/Space，不改变月 Token 的可访问描述或详情完整月值。
- `UsageRow` 的 `data-usage-model` 使用稳定的 `flash` / `pro` / `other` 键。`DashboardPanel` 传递真实点击事件的 `currentTarget`，App 只记录本次实际进入的模型键、导航代际和账户状态代际，不保存稍后会卸载的按钮引用，也不按显示名或列表下标匹配。
- 只有当前详情的“返回主面板”能携带恢复入口。详情经过设置再回首页、历史返回、普通设置返回都继续走首标题；Token/数据提示定向设置入口仍由设置面板自己的焦点逻辑负责。
- 页面和导航代际一起提交；焦点在提交后的 RAF 内再次检查当前请求、当前提交页面和账户代际，再在当前首页 DOM 中查找重挂载的原生按钮。账户版本、configured 状态、配置可信状态、账户清理状态、任一通道凭据暂停状态变化都会撤销旧入口。凭据失效后又恢复也不复活旧入口。
- 原模型行不存在（例如 `other` 消失）、已禁用、隐藏或不能取得焦点时回退当前首页标题。不按下标误聚焦另一行，也不等待数据回来后突然补聚焦。
- 新导航意图、后续键盘/指针交互、控件焦点变化、窗口失焦或隐藏都会取消旧请求。窗口重新显示不会补执行旧 RAF；后续明确导航仍可正常聚焦。首次可见性查询的迟到结果不能覆盖更新的显隐事件。

## 真实 DOM 验证准备（待执行）

使用维护者本地的浏览器 DOM 测试环境或 Windows 调试环境，挂载真实 `App`，以 `react-dom/client` 的 `createRoot` 和 `StrictMode` 渲染真实组件。IPC 只返回合成账户和用量数据，不接触真实凭据或网络。保留实际原生 DOM、`.focus()`、`document.activeElement`、`isConnected`、事件冒泡与焦点事件，不能用 `createNodeMock` 或 `.focus()` 计数代替。

准备 Flash、Pro、其他三个模型，月值至少包含 `0`、`123,456,789` 和未知，且月值与七日汇总不同。账户 A/B 使用不同凭据版本。异步用量响应与配置事件可控。浏览器页面须处于前台且拥有焦点；测试框架应使用真实键盘/指针输入，不只调用 React props 回调。

为覆盖竞争窗口，测试夹具可暂停 RAF 队列并逐帧释放，记录并尊重 `cancelAnimationFrame`；还可在隔离用例中故意调用已取消回调以检查所有权守卫。每次断言需区分“React 已提交”和“下一帧已释放”，并保持原生 DOM 的焦点行为。夹具中暂停 RAF 不等于修改生产计时逻辑。

## 真实 DOM 回归矩阵（待执行）

1. **三个模型分别往返。** Tab 到对应首页整行按钮，保存该 DOM 节点引用，分别用 Enter、Space、鼠标打开。提交并释放 RAF 后，`document.activeElement` 是对应详情的 `h1`。激活“返回主面板”，提交并释放 RAF 后，焦点必须等于当前 `.dashboard-panel button[data-usage-model="对应键"]`，而非首页标题。旧入口应已断开，恢复的按钮应是不同的已连接 DOM 节点。Tab/Shift+Tab 从该行的原生顺序继续移动。
2. **恢复按模型键且仅一次。** 依次 Flash → 返回 → Pro → 返回 → 其他 → 返回，重复同一模型往返，并改变显示名、月值与 `usage.models` 顺序。每次聚焦本次入口键，不受先前入口或数组下标影响。恢复后普通数据刷新不能再次聚焦该行或标题。确认按钮仍只有一个、无自定义 Enter/Space 接管，`aria-describedby` 仍含当前完整月值及月来源。
3. **原入口消失。** 从其他模型进入，详情打开期间发布不含 `other` 的新用量快照，再返回。首页提交后应聚焦首页 `h1`；不得聚焦 Flash/Pro、已卸载节点或 `body`。随后再发布含 `other` 的快照，不能补抢焦点。额外通过夹具将目标按钮设为 disabled/hidden，检查标题回退。
4. **账户与凭据状态变化。** 在详情内分别模拟账户 A → B、清除 Token、API Key 版本变化、配置读取失败/恢复、凭据失效后同版本成功恢复、清理未确认状态变化。返回均只聚焦当前首页标题，不能恢复旧入口。额外让事件恰好发生在返回已提交与 RAF 之间：旧帧不得读取旧账户 DOM，新账户提交后才允许标题回退。普通刷新、偏好设置变化、非凭据网络失败不应凭空丢失合法的模型入口。
5. **主动改变焦点优先。** 暂停返回 RAF，待首页已提交后，Tab/Shift+Tab、点击或调用真实 DOM `.focus()` 选中其他可聚焦控件，再释放帧。用户选中的元素必须保持焦点，不能被模型按钮或首页标题抢走。先移到其他控件再移回原位置，也不能复活请求。对“进入详情待聚焦标题”的窗口同样检查。
6. **新导航覆盖旧导航。** 暂停详情进入或返回的 RAF，发起设置/历史/另一个模型的合法新导航，提交新页面后释放全部队列，包括隔离调用旧回调。只有最新页面的焦点目标可生效，不得聚焦当前页面中的同名或首个错误元素。若新导航被未保存设置拦截，旧页 RAF 也不能抢对话框焦点；保留原有取消、保存并离开和放弃流程。
7. **只有明确详情返回才恢复。** 模型详情 → 普通设置 → 首页应落到首页标题。首页 → 历史 → 首页及首页 → 普通设置 → 首页仍落到标题。普通设置、历史和详情的首次进入仍聚焦各自首标题。Token/数据提示定向入口继续聚焦对应目标，不被 App 的通用标题 RAF 覆盖。
8. **隐藏、失焦与卸载。** 返回待执行时隐藏到托盘、触发文档 hidden、切换到其他窗口，或卸载 App，然后释放旧回调。不得出现后台聚焦或失效节点聚焦。重新显示、重新获取焦点后不得补执行旧请求；再次明确打开/返回详情仍正常。让首次 `is_main_window_visible` 查询延迟，先发送较新的 hidden/shown 事件，再返回相反的旧查询结果，旧结果不得改变最新显隐判断。
9. **React 提交边界。** 用真实 `createRoot` 的 StrictMode 重放及可中断更新覆盖上述流程。让最新导航/账户更新已产生而 React 尚未提交，释放上一页 RAF，确认不提前聚焦。完成最新提交后，只允许当前请求执行一次。中止渲染、重挂载与晚到数据不可恢复已被新导航或用户交互取消的请求。

不要把已取消回调的模拟、React renderer 的 props 调用、静态选择器检查或 ARIA 属性存在，记录成真实键盘焦点通过。
