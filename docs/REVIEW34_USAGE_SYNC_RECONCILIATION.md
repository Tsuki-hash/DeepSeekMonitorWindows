# R34 网页登录状态对账

本轮只做源码修改与静态检查。没有运行测试、类型检查、构建、脚本或应用；下述回归是已编写的用例，不是通过记录。

## 修复范围

- `src/usage-sync-reconcile.ts` 为设置页拥有的活动网页登录安排每轮完成后 2 秒的单飞对账。安装成功的监听不重复安装；安装失败的监听独立重试，失败尝试的回调先撤销所有权。状态/配置读取失败显示恢复提示并在后续轮次重试。
- `src/settings-state.ts` 以页面生命周期、本地操作序号、原生 requestId/generation 和监听事件序号共同核对读取结果。开始命令尚未取得原生 generation 时，不用旧会话快照结束新操作。手动保存、清除、取消、新会话与卸载会撤销旧读的发布资格。
- capture/ended 事件丢失时，匹配的终态会先重新读取配置再结束等待。原生 status 没有成功原因，所以只说明“同步已结束，当前配置已核对”，不凭 configured=true 或任意凭据提交断言该会话成功，也不清理手动草稿。
- 取消 no-op 的状态读取排在旧状态读取之后，并实际发起新读取，不复用取消前快照。取消期间暂停自动对账的结果处理，保留明确取消回执的反馈。
- 事件仍提供即时更新；缓存预扫描 `synced=true` 的既有配置补读保留。退出设置后不保留后台计时器、监听回调或页面写入资格。

## 已编写的回归

`src/usage-sync-reconcile.test.ts`：六个纯协调器用例，覆盖空闲停止、活动轮询、慢读单飞、失败重试、监听安装恢复、失败回调撤销、在途读取卸载后晚成功/失败、迟到监听清理和保留的旧 timer 回调。

`tests/settings-transactions.test.tsx`：末尾追加十七种真实 hook 场景，分别在 legacy/concurrent React renderer 中执行。使用合成 IPC 与显式推进的 timer，覆盖：

1. capture 丢失但通用配置事件到达，终态补读配置且保留手动草稿、晚重复 ended 不改反馈。
2. 任意 configured 更新不结束仍活动的登录；丢失 ended 后不冒认同步成功。
3. 慢 status/config 读跨越新会话，不结束新会话、不发布旧配置。
4. 取消胜过旧活动状态读取；取消 no-op 等旧读结束后再取新状态。
5. status/config 读取失败无需第二次点击即可重试。
6. capture 监听安装失败独立恢复，其他监听不重复注册。
7. 卸载后的晚成功/失败不继续读配置、不安排 timer；重挂读取原生终态。
8. 终态配置补读已在途后分别 Clear、Forget 或继续编辑，再让旧补读晚成功/晚失败。直接断言新草稿、账户版本、已提交配置和清除/忘记反馈不被覆盖；仅编辑时仍允许展示当前状态读取失败，并在恢复后结束等待，不保存或消费新草稿。

这些合成测试不模拟 WebView2 调度、系统 timer 节流或真实原生 emit 故障。2 秒是每轮结束后的计划间隔，不是硬实时保证。仍需在允许运行后执行类型检查、单元与组件回归，并在 Windows 上验证新网页登录、缓存登录、关闭登录窗、取消、丢通知和重进设置。
