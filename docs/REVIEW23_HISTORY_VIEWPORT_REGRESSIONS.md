## 原始反例

第二十二轮中，布局提交和 ResizeObserver 都先比较旧布局、恢复阅读位置，再写入视口快照；但 `onScroll` 直接读取当前 DOM 并覆盖快照。浏览器会延迟派发 `scrollLeft` 写入引起的 scroll，因此以下顺序会丢失尚未协调的第二次尺寸变化：

1. 容器宽 81px、`scrollLeft = 81`，受保护的六月柱位于内容坐标 135–159px。
2. 宽度减至 54px，observer 恢复六月柱，写入 `scrollLeft = 105`，该写入对应的原生 scroll 尚未派发。
3. 宽度再减至 27px，六月柱已经在当前右边界 132px 之外。
4. 第 2 步产生的旧 scroll 先到。旧 `onScroll` 将 27px 写进基线，后到 observer 误判布局未变化，停在 105px，六月柱完全滚出视口。

这些数字是几何替身的受控反例，不是 Windows 实测日志。

## 修复

`onScroll` 现在调用与提交和 observer 相同的、最近一次已提交的 `syncViewport`：先比较新布局和已协调基线，有变化则执行原生产 `restoreViewport`，之后才保存新快照。上述第 4 步因此仍能看到旧的 54px 基线，并将位置修正为 132px；后到 observer 与修正后产生的迟到 scroll 只读已稳定布局，不重复横移。反序由 observer 先完成相同修正。

没有增加“忽略下一次 scroll”、定时器、待忽略事件计数或过期目标位置。scroll 事件本身不提供旧位置；处理时始终读取当前 DOM 位置。若当前位置已经不同于上次协调后的值，并且不是新布局的自然夹紧：

- 纯 append／prepend 仍按存续日期的统一位移恢复锚点。
- 若同时看到容器宽度、柱宽或柱间位置发生非统一变化，保守保留当前像素位置，不再套用旧几何的日期锚点。用户可能已经按新布局阅读，不能再从旧坐标推断应看的位置。
- 不再用旧宽度修复保护柱的裁切。这样第二次缩窄后，用户刚刚主动把保护柱留到仅露出 1px 时，迟到的程序滚动通知不会又把它拉回。

也没有调用 focus／blur。

自动跟尾只沿用已协调基线中确认的贴尾状态，不把同帧新位置与旧 `rightEdge` 相等解释为跟尾意图。若用户滚到旧尾部的通知尚未被处理，数据又发生 append，仅凭当前位置无法区分“先滚到旧尾再追加”与“在新布局中滚到旧尾坐标”；此处保守保留当前日期阅读位置，而不是猜测先后并追到新尾。用户贴尾位置一旦在有效布局中被记录，后续无保护 append 继续正常跟随。这是本次明确的边界，不声称能识别所有原生事件的真实来源或先后。

其他既有策略保持：首次有效布局跳尾；按日期恢复 prepend 锚点；纯 append／prepend 保留用户选择的部分裁切；只为尺寸变化增加的遮挡做保护；实际 `ownerDocument.activeElement` 优先于无法同时显示的固定柱；Escape 可收起明细而不移走真实焦点；无效布局不覆盖有效基线；每日／每月切换、ResizeObserver 及 resize 回退清理保持。

在 legacy／concurrent 两种配置下新增或扩展：

- 固定柱、显式 activeElement、Escape 后 activeElement 三种保护身份；首次缩窄产生迟到 scroll，第二次缩窄后覆盖 scroll 先到和 observer 先到两种顺序。断言 81 → 105 → 132 的阅读位置、只发生两次必要修正、剩余事件／重复 observer 不再写滚动位置，并保留选择和焦点身份。
- 相同三种保护身份下，第二次缩窄后用户主动将左侧或右侧裁切到仅露 1px，随后先派发上次程序滚动的旧通知。断言读取最新位置、不用旧宽度消除用户新选的裁切；紧接的 append／prepend 和剩余通知继续保留像素位置。
- 连续宽度变化中穿插 append 提交；提交先于 observer／scroll 时仍协调布局。用户把保护柱留到仅露出 1px，随后 append 不移动、prepend 只做日期偏移，后续缩窄未增加左侧裁切时也不拉回。
- prepend 的程序滚动通知仍排队时，再缩窄并由用户主动滚离保护柱；旧通知读取最新用户位置，不恢复过期位置，不吞后续用户通知；紧随其后的 append 仍保留新阅读位置。
- 固定柱与真实焦点无法同时容纳，第二次缩窄由迟到 scroll 先处理时仍让真实焦点优先，明细固定身份不变。
- 迟到 scroll 遇到零宽布局不覆盖上次有效基线；恢复为窄布局仍保护原可见焦点；切成每日模式后 observer 已断开，剩余通知不触发月视口滚动。
- 用户在新窄布局滚到旧 rightEdge 坐标时不误跟新尾；未记录的用户贴尾与 append 同帧时保留读取位置；记录过的贴尾仍跟随下一次 append。移除首月造成自然夹紧时不误认为用户主动滚动，保留原日期像素位置。
- 柱宽 24 → 30px 或仅间距 3 → 9px，与用户按新几何横滚到 132px 同帧时，迟到通知不按旧坐标额外移动到 162px；随后纯 prepend 仍只加新步长 33px，保持第五个月的屏幕位置。
- 无 clientWidth、rect、ownerDocument 的非 DOM ref 替身在非空、append、空数据时主动派发 scroll，保持安全退出。所有组件卸载仍检查 observer／定时器／相关监听器清理；既有 resize 回退清理用例保留。

以上只是受控通知队列、数值几何和显式焦点替身，不实现浏览器 CSS 布局、真实原生事件调度／合并或焦点默认动作。StrictMode 包装不等于 StrictEffects 通过，非 DOM ref 用例也不等于单独执行过服务端渲染。第二十至二十二轮现有回归均保留且仍待执行。
