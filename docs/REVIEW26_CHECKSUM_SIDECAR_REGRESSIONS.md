# 第 26 轮：校验和 sidecar 独占新建与源文件稳定性

## 状态

本轮仅修改源码、补回归文本并静态审阅。**未运行构建、测试、PowerShell 脚本、安装包或应用，未提交。以下命令和场景均待用户在本机执行，不是通过记录。**

第 27 轮补充：[释放证据与负变异](REVIEW27_CHECKSUM_EVIDENCE.md) 和 [输出对象/路径绑定](REVIEW27_CHECKSUM_BINDING_REGRESSIONS.md)。当前生产脚本两处 `Dispose` 均存在；原测试的字符串顺序与子进程退出后检查不足以单独证明释放，不能据此声称已有生产泄漏。以下历史矩阵须连同第 27 轮新增场景一起验收。

原实现先 `Get-FileHash`，再对 `<installer>.sha256` 调用 `WriteAllText`。预先把 sidecar 硬链接到安装包或哨兵文件时，后一个操作会截断同一文件对象；即使不使用链接，哈希后重新打开路径也没有保护源包与记录的一致性。

## 生产行为

- `release-checksum.ps1` 现在要求 PowerShell 7+ Core、Windows、本机 NTFS。复用 `release-file-snapshot.cs` 的 `LockedFileSnapshot`：源文件通过拒写/拒删的读取句柄打开，以卷序列号和 file index 确认身份，并锁定规范卷路径的全部祖先。它拒绝无法确认的文件系统、路径、共享冲突或身份；没有“锁失败但继续生成”的降级。
- 哈希只使用该句柄读出的同一字节快照。源句柄与祖先目录句柄保持到 sidecar 写入、flush、读回与关闭全部完成后才释放。没有额外按路径重新读取安装包。沿用 helper 的单快照大小限制（不大于 `Int32.MaxValue`），超限失败，不回退为未锁定哈希。
- sidecar 路径为锁定的 `LockedPath + '.sha256'`，使用 `FileMode.CreateNew`、`FileAccess.ReadWrite`、`FileShare.None` 原子独占新建。此前已存在或在创建前并发出现的普通文件、硬链接、符号链接（包括悬空链接）和目录都应明确失败，不能覆盖或删除重建。没有 `Test-Path → 覆盖` 窗口。
- UTF-8 不带 BOM、严格编码；格式为小写 SHA-256、两个空格、实际被锁文件的文件名和一个 LF。不允许控制字符/路径分隔符或损坏 UTF-16 静默变成不正确的记录。
- 新建后只使用同一独占句柄写入、`Flush(true)`、检查长度和逐字节读回；不关闭后按路径重新打开校验。任何创建、写入、flush、读回或释放错误都非零结束，不输出成功路径。失败后可能留下空或部分 sidecar，它是**未确认成功的文件**；脚本不会删除它，也不会删除并发替换到同一路径的对象。下次运行仍拒绝覆盖，由维护者核实后决定怎样处理。
- 成功只输出实际使用的规范卷 GUID 路径，例如 `\\?\Volume{…}\release\setup.exe.sha256`。输入的盘符、SUBST 或重解析路径别名不作为后续写入依据；输出位于最终被锁文件所在的规范目录，记录也使用该实际文件名。不要假定输入别名旁的不同同名文件就是返回结果。
- 这是生成校验和，不是对包来源、签名、版本、安装/升级或应用行为的验收。锁在命令结束时释放，不能保证文件之后永不被修改。

`Get-Item` 和 C# 加载使用 `-LiteralPath`；文件内容/输出使用 .NET 的逐字路径 API。`[]`、中文、空格、单引号与长路径不会走 PowerShell 通配符匹配。若系统或路径不能支持要求的操作，明确失败，不改写路径或忽略错误。

### 自动编写的合成矩阵

1. 新输出完整内容、无 BOM、退出 0、返回路径与 sidecar 的文件身份相同。真实源码树含 `run [ab]`，旁路 `run a` 中的同名 C# 是 `#error`；输入也有完整路径可匹配、内容不同的旁路文件，错误的非 LiteralPath 必须暴露。
2. 中文、空格、`[]`、单引号和超过 300 字符的实际路径；不以孤立方括号目录或仅普通短路径冒充覆盖。
3. 预先存在的普通输出、指向合成源包的硬链接、指向哨兵的硬链接、输出目录均失败；源、哨兵、旁路内容不变，普通输出内容不变。硬链接使用现有 `CreateHardLinkW` 测试 helper，启动前/失败后用 volume serial + file index 检查身份，不能以字节相同或复制替代。
4. 源文件已被可写句柄打开时拒绝，sidecar 尚未创建。
5. 哈希完成后、真正 CreateNew 前的事件屏障：另一个参与者新建普通 sidecar 或指向哨兵的硬链接。主流程必须失败且保留另一个参与者的完整输出，不能因最初“尚不存在”就覆盖。
6. `AFTER_HASH` 和 `BEFORE_FLUSH` 双屏障：直接/通过硬链接打开源文件写句柄、重命名源文件及祖先必须被共享冲突拒绝；后一屏障还检查 sidecar 的写入/重命名被拒绝。仅接受实际 Win32 32/33，ACL 等其他错误不能算锁成功。子进程结束后相同文件可打开写句柄、祖先可重命名再复原，但这只证明终态可访问，OS 退出清理也可能做到；生产释放证据必须另看第 27 轮同宿主仍存活时的探针。所有实际变动只涉及新建合成夹具。
7. 仅在测试副本注入：写一个字节后抛异常；关闭新句柄使真实 `Flush(true)` 调用失败；保持长度但改变首字节使读回失败。三者都必须非零、无成功路径、原件不变，并保留新建但未完成的 sidecar。关闭句柄后的 Flush 故障只测错误传播，不能证明最后的 Dispose；第 27 轮另用保持句柄打开的 FileStream 子类，在真实 `Flush(true)` 调用处抛错后验证生产 finally。两者都**不等于真实磁盘满、介质故障或系统断电实测**。
8. 输入不存在/输入是目录时失败，不生成 sidecar。
9. 预建指向源包/哨兵/不存在目标的 sidecar 符号链接，全部失败；链接保留，目标内容不变，悬空目标不得被创建。测试用 `OPEN_REPARSE_POINT` 打开链接本体，比对前后 volume serial + file index 和 `FSCTL_GET_REPARSE_POINT` 的完整原始数据，不能只检查 ReparsePoint 属性来声称未替换/改向。测试使用逐字 `CreateSymbolicLinkW`，必须有当前用户已具备的符号链接权限或 Developer Mode。脚本不改变系统配置；权限缺失或链接创建失败会终止整套回归，不跳过后声称完整通过。

主脚本没有测试模式或可绕过锁的环境开关。屏障和故障只替换隔离副本里的唯一注释锚点。

### 结果判定与附加故障场景

- 完整通过要求退出 0、全部逐断言通过、唯一 `RELEASE_CHECKSUM_WINDOWS_SUMMARY`、`summary.json` 的 `completed=true`，且 `cases` 与实际 `case N/result.json` 一致、断言数与 `assertions.json` 一致。`realInstaller` 始终是 `NOT RUN`。
- 所有证据保留；失败查看 `failure.json`、已完成用例的 `result.json` 及 stdout/stderr。只见某条 PASS、sidecar 文件或文件中看似完整的 hash，不能当成命令成功。缺完整汇总就是整套未完成。
- 用户可在另一个全新、可丢弃 NTFS 夹具目录上追加：明确拒绝新建文件的临时目录 ACL、已有 sidecar 的独占锁、磁盘/配额不足、helper 缺失/无法加载、非 NTFS/网络盘输入。必须失败、无成功路径、不修改既有源/输出。不可为此改真实发行文件 ACL、系统目录或生产安装位置；需要改变权限/磁盘设置的准备步骤由用户决定并执行。
- 如需检验持有锁期间直接截断、经已有硬链接覆盖、删除或替换，只对新建夹具副本操作，要求真实共享冲突且原内容/身份不变；测试程序释放后可完成同一操作。不可在真实发行原件上做破坏性验证。
- 尚未运行的场景要保留 `NOT RUN`。纯函数、Windows 合成回归、真正候选包校验和生成，以及实际安装/升级验收是四种不同证据，不相互替代。
