# 第二十四轮登录注入脚本候选队列修复与回归

范围：P2。原脚本在 A 的 `usage_token_captured` 尚未完成时忽略所有新 Token。即使 B 只出现一次、随后 A 验证失败，也不会尝试 B；若 B 没有进入可扫描缓存，本轮同步可能一直等待。

**状态：仅修改生产源码、回归源码和文档，进行了人工静态检查。未运行构建、测试、脚本、格式化工具或应用；未做 Windows / WebView2 使用验收，未提交。以下均为实现契约和待执行断言，不是通过记录。**

## 生产行为

- `src-tauri/src/sync_script.rs` 仍同时拦截 fetch 和 XMLHttpRequest 的 Authorization。两条通道共用同一条 IPC 单飞通道，每次仍只调用 `usage_token_captured`，仍使用创建登录窗时绑定的 generation。
- A 在途期间，新的不同候选进入等待队列。队列最多两个等待槽，保留最早未试候选以及最新不同候选。例如 A 在途、依次收到 B/C/D，保留 B/D；A 失败后先验证 B，B 失败后再验证 D。仅有 B/C 时都保留，不因 C 抢走 B 的机会。
- 当前在途值和等待队列按完整字符串去重。重复的 A 不进入等待队列，重复 B 不重置 B 的顺序，也不会挤走另一个等待候选。被容量策略替换的候选不承诺获得尝试机会；这不是一个保存所有历史 Token 的无界队列。
- 一个候选被取出后不会因失败自动放回。异步拒绝、同步抛错、非 Promise 返回、无效 `then` 或抛错的 `then` getter 都释放单飞状态并推进其他候选。后续真实请求再次携带这个值时仍允许重试，但失败本身不会重新调度自己。同步异常后的推进放在 microtask，避免递归调用增长。
- 正常 Promise 与 thenable 通过 `Promise.resolve` 归一化，每个结果只处理一次。非 Promise 返回不被当作成功确认。真实 Tauri bridge 本来就返回 Promise；对损坏 bridge 的恢复不代表能够证明该 bridge 在原生侧执行了什么。
- bridge 尚未出现、不可调用或者访问 bridge 时抛错，队列保持有界并停止主动尝试，不循环重试。下一次请求或 Finished-load 的重注入可继续尝试。重注入不重复安装包装、不丢弃正在验证或等待的候选。
- 成功即终止本页捕获，清空候选引用并丢弃 B/C。迟到的拒绝、旧包装调用以及重注入均不能重新开始该文档的捕获。若页面随后安装了别的包装，清理不会覆盖它；只恢复仍指向自己包装的 fetch / XHR。

## 内存、取消与凭据边界

- 最多保留 1 个在途值和 2 个等待值，每个候选最多 16 Ki 个 JavaScript 字符，仍要求至少 20 字符。上界针对本 hook 保留的候选内容，不包括原网页请求、浏览器内部副本或 IPC 自身的内存。超长候选不送入这个 hook 的验证队列；没有修改缓存扫描器或手动粘贴的规则。
- Token 仅在闭包内存和既有授权 IPC 参数中使用，不写日志、窗口标题、DOM、Storage、磁盘或公开 marker 字段。marker 只有不返回候选的 `resume()` 控制函数。清空意味着释放自身引用，不承诺 JavaScript 引擎安全擦除已经分配的字符串内存。
- `pagehide`、`unload`、成功结果，以及后端两种明确撤销错误“同步已取消”“同步已取消或已被新的操作替代”，都会清空候选引用并终止该文档的捕获。String 拒绝和带相同 message 的 Error 都识别。其他 Token 验证失败仍推进队列，不能被误认成整轮取消。
- 后端取消/替代后通常关闭原窗口，页面真正销毁会释放整个 JavaScript realm；IPC 也会返回明确撤销错误。**如果窗口尚未销毁或关闭失败，且撤销错误尚未回到页面，不能声称候选已经立即清空。** 此时仍依赖现有 Rust generation / lifetime / 锁内 commit 守卫阻止旧候选验证或写入。没有增加轮询取消状态、放宽来源权限或绕过后端守卫。
- 这些内存候选不能改变提交归属：A 与 B 均携带相同的原窗口 generation，后端继续在验证等待和真正提交时检查代际及窗口 lifetime。新文档由自己的初始化脚本安装新 hook，旧文档的迟到结果不能修改它。

## 真实源码回归入口

`tests/sync-script.test.mjs` 使用 Node 内置 `node:vm` 直接读取并执行 `sync_script.rs` 的 Rust 原始字符串。generation 替换与生产创建窗口处相同，断言唯一的 IPC 参数插入点。测试没有复制 `deliver`、队列或状态机实现，也不依赖真实 Token、缓存文件、网络或新增依赖。

测试只用可控替身替换浏览器请求、页面事件和 Tauri IPC Promise。每个成功/失败顺序均通过生产 hook 产生真正的调用记录，核心 B 回归从未重发 B，也没有给它提供缓存兜底。待执行覆盖包括：

1. fetch A / XHR B 及反向组合，A pending 时仅记录一次调用；A 失败后 B 自动进入 IPC，参数仍只有 Token 与原 generation。
2. 大量 A/B 重复和重复注入维持一个 in-flight、一个 B；失败完队列空闲，不自动重试 A/B。新的真实观察才允许再试 A。
3. B/C/D 替换和 500 候选突发，只保留最早及最新等待项，不把 B 饿死；原队列没有增长为历史列表。
4. A 成功丢弃 B/C；旧包装调用、重注入、后续请求不能追加捕获。成功后移除页面监听并恢复自己的包装，不覆盖网页后装的包装；只读属性或监听移除异常不能使 Promise 完成处理器抛出新拒绝。
5. pagehide / unload 先发生，随后成功或失败均不能推进 B/C；重复销毁通知幂等。另一个新文档可独立使用新 generation。
6. 两种明确撤销错误，String / Error 两种载荷，以及同步撤销，均终止等待候选。普通验证失败继续推进。
7. 同步抛错、undefined/null/普通值/普通对象返回、非函数 `then`、抛错 getter、拒绝 thenable 均不会永久锁住 pending。thenable 重复完成、成功后抛错不能先成功又重放队列。
8. bridge 晚到、bridge accessor 抛错时不忙重试，重注入后仍恢复已保存的候选；不需要重新发送平台请求。
9. 最小长度、16 Ki 字符边界、非 Bearer、fetch 的 object / pairs / Headers / Request / init override，XHR 以及缺失某通道和非平台 host。
10. 原始请求的 receiver / 参数 / 返回值保持不变，读取头部抛错也不吞掉原始平台请求；日志、标题、cookie 与 Storage 替身没有写入。

`package.json` 的 `test:unit` 在原有 `src/**/*.test.ts` 之外显式加入本 `.mjs` 文件，因此 `npm test` 及调用 `npm test` 的源码/发行门禁都会执行它。只运行这个 Node 文件不等于前端完整门禁、Rust 回归或 Windows 真实验收通过。
