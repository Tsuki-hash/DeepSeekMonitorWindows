## 原始反例与修复范围

第 21 轮的受保护日期修正应用于每一种 `layoutChanged`。固定旧月份后，用户主动横滚，令一根 24px 柱仅露出 1px；跨月快照仅在右侧 append，容器宽度和旧柱几何没有改变。旧逻辑仍将这根柱恢复为完整可见，额外移动 23px，破坏原日期锚点和阅读位置。真实柱焦点、Escape 收起明细后仍留在按钮上的真实焦点也受影响。

`HistoryTrend` 现在先恢复原日期锚点，再判断是否需要保护可见性：

- 只有容器确实缩窄，或该受保护柱本身的宽度发生变化，才进入遮挡判断；仅月份数量／滚动总宽度改变不构成理由。
- 比较锚点恢复前后的左右裁切量，某一侧新增超过 0.5px 遮挡，或柱宽缩小使原先剩余的可见像素完全消失，才执行原有完整可见修正。原先左侧裁切在缩窄后未加重时保留其像素偏移；变宽也不会拉回既有裁切。
- 无尺寸变化的纯 append 保留原 `scrollLeft` 和日期像素位置；prepend 仍通过日期身份移动 `scrollLeft`，同时保留柱的原像素位置和用户选择的裁切状态。
- 保留此前的首次跳尾、无固定／真实焦点且原本贴右才跟尾、未派发 scroll 事件的原生滚动优先、ResizeObserver／窗口 resize 回退、无效布局保护。真实焦点仍由所属文档的 `activeElement` 核对，Escape 不移走焦点；缩窄后固定与真实焦点无法同时容纳时仍优先真实焦点。

“全部”范围预建当前月之前的月份槽位，因此跨月新快照是实际 append 场景。“继续加载”通常只是回填 value，不能拿它代替 append 或直接组件 prepend 的验收。

## 已添加但未运行的回归源码

现有 `tests/history-trend-interactions.test.tsx` 的组件 runner 保持不变。新增用例在 legacy／concurrent renderer 两种配置下覆盖：

1. 固定、显式模拟 activeElement、Escape 后模拟焦点三种保护身份；左边或右边仅露出 1px；scroll 事件已派发或尚未派发。纯 append 后断言 `scrollLeft`、受保护日期和首个可见日期的像素位置不变，且无额外滚动写入。
2. 同一场景接着触发无变化的 ResizeObserver，再 prepend 一个旧月；前者不写滚动位置，后者只做日期锚点位移，保留原裁切。过程中不请求 focus／blur，选中与明细状态、模拟焦点身份保持。
3. 缩窄导致新的右侧裁切、原有右侧裁切加重时恢复受保护柱；缩窄但原有左侧裁切不变时不移动；变宽时左／右既有裁切均不触发额外修正。
4. 柱宽由 24px 增至 30px：原有左侧裁切量不变时只保留日期锚点；右侧遮挡增加时执行可见性修正。柱宽减至 18px：左侧原先仅剩的 1px 消失时修正，右侧遮挡消除时只保留日期锚点。
5. 固定柱和真实焦点相距过远、缩窄后无法同时显示时，真实焦点仍优先，固定明细身份不改变；仅固定柱变宽引发修正时，也不能遮挡几何未变的真实焦点。

这些是数值几何、合成事件和显式 activeElement 替身。没有执行 CSS 布局、原生键盘焦点默认动作或真实浏览器事件时序；StrictMode 包装也不能作为 StrictEffects 或 WebView2 通过证据。保留的第 20、21 轮回归仍需一起执行。
