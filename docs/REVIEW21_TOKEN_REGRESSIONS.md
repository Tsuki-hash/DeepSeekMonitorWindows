## 验证契约

1. 单月探针的 200 响应经过生产 JSON 反序列化，再与用量读取共用 `validate_usage_values`。月 `total` 和所有日 `data` 的全部条目都检查，不能用旁边的合法条目掩盖坏值。检查保留原语法与范围，并复用 R20 的 `is_negative_amount` 原始尾数判断。
2. `-1e-400`、`-0.0001e-400` 等实际负值被拒绝；`-0`、`-0.0`、尾数全零的科学计数法仍是合法零。正数科学计数法、合法小数、正数下溢的既有源数值语义不变。后续整数计数/presence 校验仍可把相应计数标为未知，探针不代替它。
3. 200 响应的坏 JSON、结构缺失或非法数值仍为 `Transient`，不等于凭据明确失效。401/403 保持 `Definitive`；网络、404/429/5xx、有界读取失败与其他 HTTP 状态仍走原有暂不可用路径。16 MiB 体积限制与网络参数不变。
4. 保留东八区当前月在前、上月兜底的策略。当前月暂时失败后继续上月；任何已请求的合法探针成功立即通过；先遇到明确拒绝立即停止。成功后不再请求其他月份。手动保存、登录 IPC 和缓存候选现在共用这一生产循环。
5. 合法空 `total/days`、空 `usage` 与 REQUEST-only 响应仍可通过凭据探针。结构缺失与空集合不是同一含义。探针只证明至少一个月的 amount 请求可用，不保证所有月份、费用端点或后续业务质量都有效，不新增 cost 查询或完整性门槛。
6. 因此，“当前月坏值、上月合法成功”仍允许接受候选；之后当前月读取返回 `invalid_data` 并不违反这份探针契约。不得为强行保证所有月份可读而改成两个月都必须成功，也不得写出单月坏值必然导致整体验证失败的断言。
7. 只有所有探针都暂时失败，或遇到明确拒绝时，候选不能提交。手动保存沿原有失败分支结束会话、返回原 Token 未更改；缓存候选的暂时失败仍保留重试机会。凭据提交、账户隔离、会话撤销和旧结果拒绝代码不变。

## 新增源码回归

## 必验矩阵

固定探针为 2026-11、2026-10。200 响应保持正确 amount JSON 结构，坏值分别放在月汇总、日明细，前后夹入合法条目。

| 当前月 | 上月 | 预期 |
| --- | --- | --- |
| `-1e-400` | `-1e-400` | 两次单月验证均暂时失败，整体暂不可用；候选不提交 |
| `-1e-400` | 合法金额或合法空业务 | 上月成功后整体通过，可接受候选 |
| 合法金额或合法空业务 | 配置为坏值 | 当前月成功即返回，不请求上月 |
| 坏 JSON/网络/429 | 合法成功 | 上月兜底通过 |
| 401/403 | 配置为合法成功 | 明确拒绝，停止，不请求上月 |
| 暂时失败 | 401/403 | 尝试上月后明确拒绝 |
| 暂时失败 | 暂时失败 | 整体暂不可用，可稍后重试 |

另逐项核对 `-0`、`-0.0`、`-0e-400`、`-0.00E+400`、`1e3`、`1E+3`、`0.25`、`1e-400` 的既有通过语义；`NaN`、无穷、空字符串、实际负数、超范围值与结构缺失仍失败。源数值通过不代表 Token 整数计数已知。
