**状态：仅修改源码、组件回归源码和验收说明。本轮未运行项目测试、类型检查、构建或应用，未执行 Windows / WebView2 / 读屏验收。以下全部是待执行项，不是通过记录；维护者自行编译、测试及 Windows 验收。**

## 原始反例与修复契约

生产路径：主面板 → 用量历史 → 模型下拉框。旧快照含模型 A，用户选 A；相同范围刷新或记账日期跨月后，新快照只含 B。旧实现继续保留 `selected=A` 并据此过滤模型卡、每日行与趋势，却从新快照生成下拉选项，导致没有任何 option 的 value 等于 A。Windows 原生 select 可能看似选择“全部模型”，实际数据仍按 A 筛选。

本轮保留原来的筛选语义：

- 每次渲染用当前完整模型列表判断所选原始模型是否存在。若缺失，直接提供一个可见、可选的 **A（当前范围未返回）** option，value 仍为平台原始模型名 A，不加后缀、不归一化、不改大小写。不增加假模型、假日记录或零值。
- 下拉框的 value 与过滤值仍是同一个 `selected`。缺失选项与新快照在同一渲染中生成，不通过 effect 自动清除筛选，不在请求完成时写回旧选择，避免与用户手动选 B／全部模型竞争。
- 缺失时显示“仍按 A 筛选”的说明，通过 `aria-describedby` 关联模型下拉框，并提供 `role=status`。未返回、查询失败、尚未加载均不代表该模型零用量。其他模型存在时也不会偷偷把总计或趋势切为全部。
- A 再次返回时恢复普通 A 选项，不能重复 value，也不能留下旧缺失提示。用户改选 B 或全部模型后，缺失 A 选项随之移除，不另建跨快照或跨账户的模型名缓存。
- 月接口中存在、但没有已返回日明细的模型仍是正常可选项；不能误标为完全未返回。每日合计仍未知，平台原始月值仍单独显示。
- 保留现有范围生命周期：同一选择的刷新、跨记账日、全部历史分页保留筛选；切换统计区间、显式更换历史月份、账户／Token epoch 变化仍清除选择和旧数据。固定历史月份不会因为当前日期变化改成新月份。全部历史依然保留已加载旧月，并区分 failed／unloaded。
- 原始数据、模型原值、汇总和隐私契约不改。CSV／JSON 继续导出区间内全部模型，不随显示筛选缩小；缺失选项及说明不进入导出，也不写入缓存或新增持久化存储。

## 组件回归源码

现有 `tests/history-lifecycle.test.tsx` 已由 `npm run test:components` runner 注册。本轮新增 34 个待执行用例（legacy 与 concurrent renderer 各 17 个）：

1. 本月与历史月份的 A → B → A 快照替换：在途时保留旧视图，完成后 A 缺失选项、提示、未知合计、空模型卡／日明细／来源表以及每日趋势保持一致；A 恢复后选项去重、值与费用趋势恢复。
2. 本月手动刷新与隐藏窗口后重新显示，上月、近 30 天跨月：时钟变化本身不发请求，刷新提交 B 后保留明确 A 筛选，再选 B／全部模型立即显示对应数据。
3. 跨月空数据、失败且无可保留数据、失败但保留同月成功快照分别处理；失败重试恢复后 A 普通选项复原，未知不被补零。
4. 月来源独有模型仍可选择；包含斜杠、空格、冒号和“（当前范围未返回）”字样的原始模型名按完整原值比较，不把展示后缀当数据值。
5. 全部历史保留旧月 A、新月份仍未加载；刷新已加载范围全变 B 后显示缺失 A；继续加载更早月份出现 A 后恢复普通选项，同时不丢旧月和 unloaded 边界。
6. 用户选全部模型或 A-two 与返回 B 的 Promise 完成处于同一批次；下一次在途刷新期间改选 B-two，返回 A 后仍是 B-two 的缺失筛选，不能被请求闭包或自动清选 effect 覆盖。
7. 在缺失 A 选项存在且旧刷新仍在途时，切范围、更换历史月份、可见／隐藏时替换账户 epoch：立即按原契约重置为全部模型，旧响应不能把 A 或旧提示带回来。

共同断言包括：controlled value 恰好对应一个 option；选项不隐藏、不禁用；缺失提示可由下拉框的 `aria-describedby` 定位；未知合计不等于零；过滤模型卡、趋势、日明细和独立来源表一致。导出仍含 B 的全部模型及平台原始月值，不包含缺失选项标签。

**这些是 React renderer 状态、结构和属性断言，不验证真实 HTMLSelectElement.value、selectedIndex、selectedOptions、Windows 原生下拉绘制、弹出菜单、实际焦点、键盘默认行为或读屏播报。也不代表 concurrent renderer 验证了浏览器所有时序。**

## Windows / WebView2 原生 select 待执行矩阵

使用最终候选源码自行编译并运行。记录版本／补丁、Windows 与 WebView2 版本、NVDA／讲述人版本、缩放、文字大小、主题和窗口模式。每项记录 `PASS`／`FAIL`／`NOT RUN`／`BLOCKED`；失败附精确步骤、可见标签、实际选择值、过滤结果及截图。截图和记录不得包含 Token、余额 Key 或其他凭据。没有可控数据时标记 `BLOCKED`，不得把另一月份自然数据没有 A 当作完整验收。

建议使用维护者已有的本机合成数据或调试夹具准备：A-only、B-only、A 恢复、空日记录、月来源独有模型、失败／延迟响应及多个账户 epoch。不要通过真实账户造假用量。跨月时间应采用本机调试时钟／合成日期，不要求更改系统时区、生产账户或系统时钟。

- [ ] **原始反例，本月手动刷新**：先查询 A，选择 A；新快照只返回 B。折叠下拉框必须显示“A（当前范围未返回）”，展开后 A 缺失选项与全部模型、B 同时可见，不能看似选择“全部模型”。合计为未知，趋势为未知，A 日行／模型卡／原始月行为空；说明明确仍筛选 A。若使用开发者工具核验原生元素，`value`、`selectedOptions[0].value`、`options[selectedIndex].value` 都应为原始 A，且 options 内只有一个该 value。
- [ ] **重新返回 A**：在上一项不手动改选的情况下刷新回 A。折叠标签为原始 A，展开列表仅一个 A，缺失说明消失，A 的最新 Tokens、费用、日明细和来源月表恢复。重复 A → B → A 数次，原生选择与数据不能错位。
- [ ] **显式改选**：缺失 A 时用鼠标改选 B，再选择全部模型；分别用 Tab、方向键、Home／End、Enter／Escape 按 WebView2 的原生行为重复。用户提交选择后，各表与趋势立即服从该选择，缺失 A 不滞留。取消展开列表不能伪造一次模型切换；焦点仍可继续 Tab 导航。验证无障碍名称“历史模型”、选中项文本和缺失说明可读取。
- [ ] **跨月与窗口显隐**：本月、上月、近 30 天分别跨北京时间记账月；先保持面板可见，只应提示旧窗口，再手动刷新。再重复托盘隐藏后重新显示。旧快照显示期间下拉框与旧快照一致；新窗口仅返回 B 后显示缺失 A。不要把隐藏期间未发请求误报为缺失。
- [ ] **历史月份固定选择**：固定选一个旧月，选 A，跨当前记账日／月及隐藏再显示不能改月份或清除 A。同月 A → B 刷新应出现缺失 A；显式选择另一个历史月份应按原有契约清选为全部模型，并与该月数据一致。
- [ ] **全部历史与分页**：至少加载两批，A 只在较旧月份出现；跨月、重显、刷新不得仅按最新月 B 删除仍由旧月提供的正常 A 选项。保留旧月、failed 与 unloaded 的说明。全已加载范围刷新后不再含 A 时显示缺失 A；再加载更早月份返回 A，普通 A 选项复原，不能重复或把未加载月份补零。
- [ ] **空数据／失败／来源独有／零**：无模型的空响应或新月失败无可保留数据时显示缺失 A 与未知，不显示 0。失败但同月保留 A 成功快照时仍显示普通 A 和旧值，并保留失败提示。只有月来源返回 A 时仍显示普通 A、未知日合计及独立原始月值。真实明确零值依旧是零，不因本轮被变成缺失。
- [ ] **在途筛选与原生弹层**：延迟刷新，用户先改选 B／全部模型再释放响应；以及展开下拉框时释放响应后再选择或取消。每种事件顺序分别验证最终原生 value、可见标签和数据统一服从最后一次已提交的用户选择。不要只依靠 React props 或截图判断原生选择是否正确。
- [ ] **账户隔离与迟到响应**：A 缺失选项存在且旧查询在途时，在可见和托盘隐藏两种状态分别更换测试账户／Token；选择应归全部模型，旧 A 名称和提示消失，未取得新快照前导出不可用。释放旧响应不得恢复旧名称、旧值或旧筛选，新账户成功响应只显示自身模型。
- [ ] **长名称、布局、导出**：包括空格／斜杠／冒号／中文后缀的原始模型名在普通与缺失状态均保留原值。窄窗、放大文字、深浅主题下可识别当前选择和说明，展开可读全名。缺失 A 时导出 JSON／CSV，确认仍是全部已返回模型，来源月原值独立保留，不包含 UI 生成的缺失后缀或任何凭据。
