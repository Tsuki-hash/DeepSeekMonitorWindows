# 第二十二轮缓存候选跨轮公平性修复与本机回归

范围：P2。单个缓存文件包含 `[A, B]`，A 当前月请求在 15 秒超时，上月请求又占满整批 30 秒预算；B 未尝试，文件不能标记已读。原实现下轮重新按原顺序尝试 A，可能直到 watcher 约五分钟观察窗口结束都不请求 B。

## 生产契约

1. 当前月优先、上月兜底、单月网络参数、30 秒整批 deadline、成功/明确拒绝短路保持不变。缓存调度与手动/IPC 校验仍使用同一生产多月探针循环。没有增加费用接口或两个月都成功的条件。
2. 同一 watcher 保存每个来源的文件大小/mtime、候选序列内容指纹、候选游标、未尝试数、明确拒绝位图和公平排序序号。超时/Transient 的候选游标前进，不把它算作明确拒绝；已拒绝候选跨轮跳过。
3. 未尝试优先。首遍按来源原始顺序继续，同文件的 B 不会每轮退回所有文件的 A 后面；完成首遍后的 Transient 重试按最近尝试顺序轮转。一轮每个未被明确拒绝的候选至多尝试一次。
4. 来源快照的全部候选均明确拒绝才回写该来源的 `seen`。未试、预算跳过、取消、超时、Transient 均不能当作拒绝。跨轮拒绝位图允许多轮累计完成，避免要求所有拒绝都挤进同一轮 30 秒。
5. 只在单文件内按值去重。跨文件相同 Token 保留各自来源，不能把尚未验证的重复来源提前标为 `seen`，也不能让另一文件的存在改变本文件的候选序号。
6. 未完成首遍的来源以分组内存快照保留，路径/stamp 每来源一份。有容量时继续原目录游标收集后部文件；新批与驻留批交替优先。不能为了保护首批的 B，反过来一直不扫描第 251 个文件。
7. 准入按驻留候选的实际载荷/来源数，预留下一完整扫描批的最坏容量。只有预留不足时才暂停新收集、继续处理驻留候选。首遍完成即释放该来源的 Token 快照，仅保留不含 Token 原文的进度。不能因容量淘汰把仍未尝试的候选反复重置到 A。
8. 新扫描产出同一路径候选时，以新快照替换驻留快照；文件 stamp 或候选序列内容指纹改变，全部重置该来源的游标和拒绝位图。旧 stamp 的 `seen` 不匹配正常更新后的 stamp。既有大小/mtime 去重入口不变，内容指纹是在实际读到快照后比较，不声称能检测所有保持大小和 mtime 不变的外部改写。
9. generation/lifetime 取消仍包住实际候选请求；等待中的请求取消后被丢弃，不启动后续候选，不标该候选拒绝/成功。迟到成功仍不能越过最终 `SyncSession::commit`。成功、取消、watcher 退出和预扫描返回时，局部候选快照自然释放。
10. 不把 Token、缓存原文、内容指纹或位图写入日志/磁盘。日志仍只有候选数量与结果类别，不为本修复新增凭据输出。

## 内存与容量边界

- 原始每轮扫描仍限制为 250 个文件、32 MiB 原始输入，并保留目录枚举位置；单文件 20 MiB、目录条目数和扫描时间预算不变。
- 二进制缓存通过 `String::from_utf8_lossy` 解码，单个无效字节最多扩为三字节 U+FFFD。因此不能把 32 MiB 原始 IO 误当作 32 MiB Token String 上限。本实现为下一完整批次预留最多 96 MiB 解码后载荷。
- 跨轮驻留最多 4096 个来源、192 MiB Token 字符串内容。只保存未完成首遍的来源，不跨轮无限累积。192 MiB 是恶意/异常输入的 Token 内容上限，不是整个进程总 RAM 承诺；String/Vec/路径、扫描临时缓冲和网络响应还有各自开销。普通登录态远小于该边界。
- 全部来源的明确拒绝位图合计至多 2 MiB，来源进度表最多 4096 项。当前批次受准入保护，淘汰只遗忘已完成首遍的旧来源；遗忘不会写 `seen`，以后重读仍可重新验证。
- 排序序号达到 `u64::MAX` 时按已有相对顺序重新编号，不用饱和值作为无限重复时间戳，也不因并列时间戳突破上限或误逐出当前来源。
- 有界公平不等于任意规模候选都能在五分钟内尝试完。持续新增/改写、海量候选或每个请求都慢，仍可能让观察窗口先结束。修复保证保留下来的待试工作不会每轮被同一个 A 无进展地重置，并使目录扫描与候选验证都有前进机会。

## 预扫描、watcher 与“五分钟”

预扫描与 watcher 是独立生命周期。预扫描只执行一次；其进度和驻留快照在返回时释放。随后新 watcher 从自己的空状态开始。所以单文件 `[A, B]` 案例中，A 可能在预扫描耗时 30 秒，又在 watcher 第一轮耗时 30 秒；watcher 后续轮次会继续 B，不能把它写成“点击后 30 秒内必定同步”。不跨会话共享 Token 快照，也不把前一次同步的拒绝状态带进下一代际。

约五分钟检查只位于 watcher 每轮入口，并非整个同步的硬上限：预扫描发生在建窗前；watcher 自己先等 3 秒，再建立 300 秒入口 deadline；已进入的最后一轮扫描、最多 30 秒验证、轮询等待与目录去抖不会被该入口检查截断。系统调度和同步文件 IO 也可能延迟。因此不能报告“精确 300 秒必关窗”或给出没有运行证据的绝对总耗时上界。原有轮次上限、取消、超时关窗与事件收尾未改。

## 新增源码回归

`src-tauri/src/cache_fairness_tests.rs` 通过实际缓存文件和 `collect_cached_usage_tokens_in` 进入生产 `collect_for_round` / `verify_candidates_with` / `probe_token_with` / `while_current`。合成 Clock 与单月 Network 只替换边界：先推进合成时钟并让出 poll，再由生产 deadline 分支决定取消请求；没有复制另一套调度算法，也没有等待真实 15/30 秒。

覆盖：

- 单文件 A 当前月 15 秒 Transient，上月在整批 30 秒仍挂起。首轮只请求 A 的两个月，文件未 seen；后续轮次先试 B，B 当前月成功后不再请求上月或重试 A。
- 多个来源、跨文件同值 A，第二来源还包含 B。每个来源保持独立，未验证重复来源不提前 seen。
- 251 个实际缓存来源：首批仍有慢/未试候选时，下一轮仍调用原目录扫描器读取后批；交替优先后有效来源可完成，不把目录后部挡在首批完整排空之后。
- A/B 已明确拒绝，C 在 deadline 前未完成：先不 seen；下轮只重试 C，C 明确拒绝后才 seen。已拒绝候选不重复请求上月。
- 全部 Transient 不 seen，下一次当前月恢复可成功。
- 驻留期间文件更新，新快照替换旧游标；旧 stamp 已 seen 后大小改变，新候选重新可见。实际读到的同 stamp 不同内容也不能继承旧拒绝位。
- 独立预扫描 + watcher：允许额外重复一次 A，随后 B 可尝试，而不是声称共享预扫描游标。
- 实际 4099 个来源分页遍历、容量饱和后 `[A, B]` 仍可继续，并覆盖序号重排。位图总容量、驻留来源满额和解码后载荷预留边界另有直接断言。
- 首请求前预算耗尽：零 HTTP 请求、零拒绝位，下轮仍有完整待试候选。
- 真实 0xff 二进制缓存经有损 UTF-8 解码，候选内容超过原字节数两倍；验证三倍预留而非错误的原始字节预算。
- 实际候选请求挂起时原生 lifetime 关闭、新 generation 替代、关闭后请求永不响应三种路径；检查迟到成功丢弃、请求 future 释放、来源未 seen、旧代际无法提交。
