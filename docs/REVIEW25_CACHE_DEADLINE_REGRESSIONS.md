# 第二十五轮缓存批 deadline 同 poll 边界修复

范围：P3。缓存批外层 `biased select` 先 poll deadline 等待器；如果当时未到期，随后单月请求在同一次 poll 内同步处理响应、跨过 deadline 并直接 `Ready`，外层计时分支没有再次获 poll 的机会。原共享多月探针只检查会话是否有效，因此可能继续上月请求，或者接收过期的成功/明确拒绝。

这是代码与异步 poll 契约层面的边界分析及合成回归，不是已在真实 DeepSeek 平台、网络或 Windows 上观测到该情况的报告。

## 生产契约

1. `probe_token_with` 独立接收时钟与可选批 deadline。缓存生产调度传入同一 `now` 和本批 deadline；手动保存及登录 IPC 传入 `None`，不会读取批时钟或增加缓存 30 秒限制。原单月 HTTP 超时、响应体限制与解析规则未修改。
2. 每个月请求准入前及其响应返回后均检查。优先级明确为：已撤销会话 → 已到期批预算 → HTTP 结果。`now >= deadline` 包括精确等号，不启动下一月，不接受到期/过期的成功或明确拒绝。预算内仍按当前月优先、Transient 兜底上月、成功或明确拒绝短路处理。
3. 新结果 `BudgetExpired` 与 `Cancelled` 分开。无论是外层 timer 返回还是同 poll 守卫发现耗尽，只要候选已经实际调用过一个月请求，就按暂不可用推进该候选的首遍计数、游标和来源队龄；拒绝位保持不变，不因预算耗尽写 `seen`。原跨轮公平顺序继续生效。
4. 若首月请求尚未发出，预算耗尽不消耗来源席位、不扣首遍、不移动游标。下轮仍从原候选开始。不能把 deadline 混入 `is_current`，否则已实际请求的超时会被错当取消而丢失公平推进。
5. 取消先发生，或到期后在同一次请求 poll 返回前发生取消，都返回取消语义，不推进该候选。外层 `while_current` 仍主动丢弃挂起请求，且在结果返回时再次检查会话。因此 timer 与取消同时可见时，取消仍胜出。最终 `SyncSession::commit` 的 generation/lifetime 守卫没有修改。
6. 外层 deadline 等待器仍负责唤醒并 drop 挂起请求。新增边界检查不会抢占正在执行的同步解析，也不保证硬实时停止 CPU 工作；它保证在检查到到期后不再把响应当成功/拒绝或准入后续月份。没有延长 30 秒批预算或 watcher 窗口，也未扩大缓存、响应或请求上限。

## 待执行源码回归

`src-tauri/src/cache_fairness_tests.rs` 继续经过真实临时缓存文件、生产 scanner、`collect_for_round`、`verify_candidates_with`、`probe_token_with` 和 `while_current`，没有另写调度器。新增 `ready_response` 让单月替身在第一次 poll 推进合成时钟后直接 `Ready`，不调用 wake，也不强制先 `Pending`；已有挂起回归保留原让出行为。

- `r25_当前月同poll到达或越过deadline_丢弃响应并跨来源公平推进`：分别在 30 秒精确等号和 31 秒返回 Transient、成功、明确拒绝。显式断言整个生产验证 future 第一次 poll 就 `Ready(None)`。只启动 A 当前月、不启动上月，来源 F 的 A 已服务但不拒绝，等待更久的来源 G 的 B 下轮实际成功，不能抢先试 F 的 C 或重新试 A。真实重扫仍读出全部 3 个候选。
- `r25_上月同poll到达或越过deadline_不接收迟到结果且下轮继续B`：当前月在 15 秒直接 Transient，上月再耗时 15 或 16 秒直接返回三类结果。均不接受过期结果、不 seen，下轮实际请求同来源 B 并成功。
- `r25_timer仍Pending而首月准入已到deadline_零请求不推进`：timer 刚返回 Pending 后时钟恰好到期。仅一次 timer poll、零月请求、首遍/游标/队龄不变，下轮实际从 A 成功。与原 R23“timer 本身先 Ready”的场景分别保留。
- `r25_deadline前正常上月成功与明确拒绝仍按HTTP结果处理`：预算内当前月成功和明确拒绝仍短路；当前月 Transient、上月在 29 秒成功或明确拒绝仍按结果处理，两月 Transient 不 seen。只有同快照全部候选在预算内明确拒绝才 seen。
- `r25_同poll取消与deadline先后均不推进首遍队龄或seen`：分别先取消后到期、先到期后取消，再直接返回成功/拒绝/Transient。真实会话取消后不发上月或 B、不推进、不保留驻留 Token 快照，最终 commit 拒绝。
- `r25_deadline主动drop挂起的任一月请求_取消同时发生仍优先`：当前月或上月挂起，到期后直接 poll 生产验证，断言实际 oneshot 接收端已被 drop。仅超时则推进并下轮成功 B；同时取消则保持原游标/首遍/队龄并拒绝提交。

`src-tauri/src/probe_cancellation_tests.rs` 新增三组直接生产探针断言：首月/上月各自准入的精确 deadline 检查返回 `BudgetExpired`；取消与 deadline 先后两种顺序均返回 `Cancelled`；`None` deadline 不调用批时钟并保留既有 HTTP 成功/拒绝/兜底顺序。原 R24 手动、IPC、旧窗口、新代际和最终提交回归保留。
