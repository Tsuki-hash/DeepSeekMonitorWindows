# 第十九轮 Windows 最小化恢复回归

**状态：只修改源码、回归用例与验收说明，未运行构建、项目测试或应用。已做源码静态核对和 Rust 格式化。以下全部为维护者待执行项，不是通过记录；编译、测试及 Windows 实机验收由维护者完成。**

## 修复契约

- 托盘菜单“显示主面板”、重复启动、托盘左键、全局快捷键和托盘“退出”共用主窗口操作入口。切换只有在 `is_visible=true` 且 `is_minimized=false` 时才隐藏；可见但已最小化、隐藏且最小化都走恢复。
- 状态读取与原生操作在同一 UI 线程回调中串行完成。最小化时先调用 `unminimize`，再核验最小化已解除，然后定位、显示、核验可见状态、请求聚焦并发送显示事件。非最小化时不调用 `unminimize`，也不无条件调用 `unmaximize`。
- 最小化恢复优先使用 Windows 恢复的正常外框；原本可见的窗口也优先保留当前外框，不用上次隐藏时的旧配置把窗口跳回原位置。必要时仍沿用工作区完整矩形夹取。当前位置失效时，再尝试保存位置和托盘回退。普通隐藏窗口仍沿用保存位置优先的策略。
- 几何调整先拒绝最小化状态，最大化状态不手动改尺寸或位置；跨屏 DPI 后再次读取尺寸前再检查最小化。隐藏和退出保存位置时，最小化、最大化或状态查询失败均不覆盖已有普通窗口坐标。持久化前后检查状态，避免 IPC 查询期间状态改变时保存错误外框。
- 主窗口仍不销毁、不重建 WebView。面板 X / Alt+F4 保持只隐藏的关闭语义，未保存草稿与当前视图不因此重置。托盘退出仅在恢复路径成功后发出 `quit-requested`，仍由前端“保存／放弃／留在此页”和受主窗口权限限制的 `confirm_quit` 决定真正退出。主窗口根本不存在时保留原有退出降级行为。
- 状态读取、解除最小化、显示或事件发送失败会记录日志并中止该次操作；解除最小化或显示返回成功但实测状态仍未恢复，也不发送虚假的 shown 或退出意图。定位失败仍尽力显示；聚焦请求失败时，已真实显示的窗口仍收到 shown 以恢复前端刷新，但不继续发送退出意图。任何恢复失败都不绕过草稿协商直接结束进程。

此修复处理应用自己的唤窗／切换／退出入口，不新增 Windows 系统最小化事件对应的前端轮询策略。`set_focus` 返回成功只表示接口调用成功，不等于 Windows 已授予前台焦点；实际焦点必须实机确认。原生定位失败时也不能把降级显示记录为“完整外框已保证位于工作区”。

## 锁定依赖依据

本项目 `Cargo.lock` 锁定 Tauri / tauri-runtime-wry 2.11.2、Tao 0.35.3；未改依赖或新增 Windows API 权限。

- [Tauri runtime 分别处理 Show 和 Unminimize](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.2/crates/tauri-runtime-wry/src/lib.rs#L3489-L3495)：前者设置 visible，后者设置 minimized=false，两者不能互相替代。
- [Tauri 同主线程即时分发](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.2/crates/tauri-runtime-wry/src/lib.rs#L235-L255) 和 [Tao 同事件线程即时执行](https://github.com/tauri-apps/tao/blob/tao-v0.35.3/src/platform_impl/windows/event_loop.rs#L522-L551)：把恢复和几何读取放在同一主线程回调内，避免跨线程 setter 仅入队后就读取最小化外框。
- [Tao Windows 最小化查询与恢复](https://github.com/tauri-apps/tao/blob/tao-v0.35.3/src/platform_impl/windows/window.rs#L584-L629) 和 [窗口状态变更](https://github.com/tauri-apps/tao/blob/tao-v0.35.3/src/platform_impl/windows/window_state.rs#L314-L399)：`is_minimized` 使用 `IsIconic`，解除最小化触发 `SW_RESTORE`。
- [Tao 聚焦条件](https://github.com/tauri-apps/tao/blob/tao-v0.35.3/src/platform_impl/windows/window.rs#L175-L185)：最小化窗口不会进入正常聚焦分支。[外部坐标与定位](https://github.com/tauri-apps/tao/blob/tao-v0.35.3/src/platform_impl/windows/window.rs#L213-L256) 使用 Windows 外框；定位会清除最大化标记，因此最大化窗口跳过手动几何调整。

这些是固定版本源码依据，不是 Windows 行为已实测的证明。

## 新增决策回归文本

`src-tauri/src/tray_restore_tests.rs` 由 `tray.rs` 的 `#[cfg(test)]` 子模块加载，调用生产使用的 `apply_main_window_intent` 和位置持久化决策。现有 Rust `--lib` 测试入口会发现这些用例，无需新 runner。13 项待执行用例覆盖：

1. 可见／隐藏且最小化两种状态，三种意图均先恢复再定位／显示／聚焦，退出意图最后提交。
2. 只有正常可见窗口切换为隐藏。
3. 普通隐藏窗使用保存位置，不调用解除最小化。
4. 已显示窗再次显示／退出优先当前外框。
5. 解除最小化返回错误或无效果，不读取／修改几何、不发 shown／quit。
6. 初始、恢复后、显示后的状态查询分别失败，不冒充成功。
7. 显示返回错误或仍隐藏，不聚焦、不发 shown／quit。
8. 定位失败仍尝试显示，成功后才交给草稿协商。
9. 聚焦失败仍通知真实显示，但不提交 quit。
10. shown／quit 发送失败均报告错误，不能直接结束进程。
11. 隐藏失败保持可见，不发 hidden 或继续执行其他意图。
12. 连续切换按最新状态执行恢复→隐藏→显示，只解除一次最小化。
13. 最小化／最大化状态及查询未知的九种组合，仅正常窗口允许保存位置。

这些用例使用替身，不创建窗口，不证明系统最小化入口、Windows 消息顺序、实际坐标／尺寸、前台焦点、通知交付或前端草稿交互。维护者可先运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib tray::restore_tests` 定位问题，但过滤运行不替代现有完整 Windows 发布门禁。R17 几何回归也须在最终候选上重跑。

- [ ] **四种初态**：正常可见、普通隐藏、可见但最小化、先最小化后通过关闭／隐藏入口得到的隐藏且最小化。逐条测试显示和切换入口；只有正常可见时左键／热键隐藏，其余都恢复。每次切换不得因按下／抬起各执行一次而立即消失。
- [ ] **草稿退出**：在提醒设置等页面制造未保存草稿，系统最小化后从托盘退出。确认窗口和三选一提示可见、焦点可达。分别选择留在此页、保存后退出、放弃后退出；保存失败时保持进程和草稿。无草稿退出正常完成。重复点击退出以及保存中再次请求退出不绕过原有草稿意图所有权。
