## 修复契约

### P2 A：跨月后重试范围过期

- 本月、上月、近 30 天等滚动窗口变化后，重试目标仍只允许取旧失败月份与当前窗口的交集。
- 交集为空时不执行成功提交，不清除失败记录、不替换旧快照、不伪装恢复。第十九轮补充：日期重绘后直接提供“重新查询当前区间”；若在下一次重绘前点击旧重试入口，仍明确说明“重试范围已过期”“本次未发起查询”。顶部“重新查询历史”也继续有效。
- 只有用户选择重新查询且真实请求完成后，才能提交新窗口结果。旧成功数据存在时先保留，导出继续标记陈旧；首次失败而没有成功数据时也仍有失败状态与恢复入口。
- 固定历史月份不会随当前日期改变而失效。交集非空时仍只重试有效失败月份，不自动扩大成全区间重查。

### P2 B：整批可继续月级失败

- “全部”保留最近 12 个月一批的策略。分页边界取已完成查询的最早月份，包括月级失败，不再只取成功月份。
- 成功来源、失败集合与未加载集合分别保存。只有失败的批次也有覆盖状态快照，因此能显示“继续加载更早月份”、保留失败重试入口并导出明确的失败／未加载元数据。
- 连续 `invalid_data` / `unknown` 月级失败仍按当前分类继续本批；下一批必须推进到更早月份，最终可到 2020-01，不在同一失败批次循环。
- 失败月份仅在真实重试成功后清除，不因后续月份成功而丢失。已有成功快照与随后失败状态可以同时存在，不把旧缓存当成本次恢复。
- 未请求、尚在途或取消后没有被当前请求所有者接收的月份仍为未加载。精确集合也覆盖跨月新增的较新空洞，不依赖“最早月份之后全都查询过”的假设；这些月份不计入 `missingDates`，不补零。
- 已失败月份的日期仍沿用现有“未返回／未知”口径；失败月份另由 `failedMonths` 明确标注。只有失败没有成功数据时，总计和趋势为未知，JSON 的 `daily`、`monthly`、`sourceMonthlySnapshots` 为空。
- 明确 `invalid_data` 错误优先按稳定分类处理，即使文案提到 Token 统计或登录字段也继续为月级失败。`unknown` 是未分类，可能来自旧鉴权错误，因此保留其鉴权文本兜底；普通月级 `unknown` 仍继续。没有把所有带 `code` 的错误都视为可继续。
- 401/403 对应的 `credentials_invalid`，404/5xx 对应的 `unavailable`，以及 429 对应的 `rate_limited` 仍立即终止当前批次，不因为新游标而自动继续请求。此次不修改原生 HTTP 分类。
- 取消、隐藏、切换范围或凭据代际变化继续撤销旧请求所有权。快照、失败集合和分页边界同次提交；迟到结果不能推进边界或污染新账号。第十九轮补充：停止或隐藏不清除已提交失败及当前有效恢复入口。再次显示时，尚无任何已提交快照才补发初始查询；已有失败覆盖快照即使没有成功月份，同日也保留快照和失败重试入口，不自动扩大查询。日期窗口变化仍按既有补查策略更新相关月份，不重查整段已加载历史。
