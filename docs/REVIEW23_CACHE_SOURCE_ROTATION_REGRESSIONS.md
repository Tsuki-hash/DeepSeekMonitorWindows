## 生产调度

1. 每个来源的队龄为 `max(first_observed, last_attempt)`。新来源以当前单调序号入队，不使用 `last_attempt=0` 抢在旧待试来源前。同一快照重新扫描只更新 `last_observed`，不重置队龄、候选游标或明确拒绝位图。
2. 一次实际候选请求结束后，包括整批 deadline 导致的暂不可用，更新 `last_attempt`。来源因此跨轮移到队尾，不再只依赖会丢失的局部 `push_back`。文件内部继续原游标，明确拒绝的候选仍跳过。
3. 未完成首遍的来源优先于已完成首遍的 Transient 重试。两组内部都按持久队龄排序，一轮每个未被明确拒绝的候选至多请求一次。
4. 收集轮交替使用“新批优先”和“全体最老待试来源优先”。全体轮不是“仅非 fresh 来源优先”：老来源刚好被扫描器重新读到时，仍保有公平席位。目录暂时没有新候选时保留最近新批身份，后部目录仍有机会。
5. 如果时间预算在前置检查与 `select` 之间耗尽，且尚未发出任何单月请求，不更新服务序号、不扣首遍数量、不移动游标、不置拒绝位。后续轮次仍从原候选开始。
6. 原有 30 秒整批预算、当前月/上月探针顺序、成功或明确拒绝短路、轮询 1.5 秒至 4 秒退避、300 秒 watcher 轮次入口检查均未扩大。没有增加费用接口或额外成功条件。

## 有界公平的范围

对已准入、快照未改变、仍有未试候选的一个来源，全体最老轮不会把新来源、重读或刚被服务的来源插到它前面。假定该来源一直可调度且每个全体轮至少实际服务一个候选，排在它前面的每个来源至多占用一次全体轮；在 N 个在队来源下，下一候选至多经过 N 个全体轮获得机会。全体轮每两轮一次，因此粗略界为 2N 个有进展的轮次，而不是固定秒数。N 受 4096 来源准入上限约束。

该界不是“任意规模均在五分钟内完成”的承诺，也不覆盖取消、来源快照持续改写、未进入扫描批的来源、扫描/准备阶段已耗尽预算的轮次，或源源不断的新首遍工作下所有 Transient 重试的完成时间。单文件 `[A慢, B快]` 仍在下一轮继续 B；多文件情况下，B 可能需要让其他等待更久的来源先得到一次机会。

明确回归中的两个来源 F/G，G 在第二轮实际发出当前月请求并成功，合成验证时间 30 秒，加一次 1.5 秒快轮询等待为 31.5 秒。这个数字不包括预扫描、watcher 启动等待和真实 IO/网络调度，也不是 Windows 实测耗时。

## 原有边界

- 扫描仍为每轮最多 250 文件、32 MiB 原始输入、250ms，以及原有单文件/目录条目预算。新增扫描时钟入口与生产共用同一读取、解析、取消和目录游标逻辑；生产传入 `Instant::now`。
- 下一整扫描批仍按最多 96 MiB 解码后载荷预留。跨轮只保留未完成首遍的分组快照，至多 4096 来源、192 MiB Token 内容；拒绝位图至多 2 MiB。没有扩大内存上限或逐出仍未尝试的来源来腾空间。
- 暂停扫描只是准入背压。实际首遍完成释放驻留快照后，再从原目录位置收集尾部来源。进度表淘汰仅遗忘已完成首遍的旧来源，不会把它们标 seen。
- stamp 或候选序列内容指纹改变时，来源游标、队龄和拒绝状态重新入队。旧拒绝不能继承到新快照。仍不声称能发现所有保持大小/mtime 不变、且被已有 seen 元数据过滤的外部改写。
- 仅同一来源快照的全部候选明确拒绝才 seen。预算跳过、取消、Transient、超时或重复值都不能冒充拒绝。跨文件相同 Token 仍独立处理。
- `u64::MAX` 重排压缩保留全部服务/观察序号的相对次序。服务序号、指纹、位图不包含 Token 原文，也不写入磁盘或日志。
- generation/lifetime 仍包住真正的单月请求。关闭、取消或代际替换丢弃挂起/迟到请求，最终提交仍检查代际。预扫描与 watcher 独立，不跨会话共享候选快照。
- 五分钟仍是 watcher 轮次入口条件。建窗前预扫描、3 秒启动等待、已经开始的最后一轮扫描/验证/休眠不在精确 300 秒硬截止内。没有通过延长窗口来掩盖公平性缺陷。
