# 第二十轮预算十进制边界修复与本机回归

范围：P2，完整费用 `0.10 + 0.70` 的二进制浮点合计为 `0.7999999999999999`，原预算与 `0.80` 裸比较漏掉等号。

**状态：只修改源码、回归文本并做静态检查。未执行构建、测试或应用，未做 Windows 验收，未提交。以下断言和步骤不是通过记录。**

## 数据契约

1. 预算月额由本次响应的原始十进制金额字符串计算，逐位相加、逐位比较，不采用 epsilon、四舍五入、整数分或先求浮点和再转换。亚分及比 f64 更细的小数均保留。
2. 仅为预算增加 Rust 内部 `budget_month_cost`。`serde(skip)` 不增加 JSON 字段，`schemaVersion=2`、`monthCost`、模型/日/raw 金额与现有显示均不变。旧显示仍可能为 `0.7999999999999999`；预算相等的依据是独立精确值 `0.8`。
3. 配置仍使用既有 JSON number `monthlyBudgetCny`，不需要迁移。该 number 的最短 round-trip 十进制文本是阈值含义，如 `0.80`/`0.8` 均为 `0.8`。不会把 IEEE-754 的二进制展开当成阈值；旧 number 已经损失的原始输入位数不能复原。阈值的有效范围仍为大于 0、至 10 亿元。
4. 精确计算是非负金额的有限专用实现，不引入依赖。防御上限为规范化后的 20 位整数、4096 位小数；无法解析、非有限、负数、源金额旧范围不合法、超精度或累计溢出均返回未知，不截断、不静默改零。合法 `0` 和 `-0` 保持明确零。正数下溢如 `1e-400` 保留精确非零；超限如 `1e-4097` 失败关闭。预算总额仍限制在 `[0, 1e12]`，上界也由精确值检查。
5. 同一原始模型先汇集全部片段再判断金额存在性。空片段、REQUEST-only 片段不污染同模型有效金额；不同旧别名、Pro、未知模型分别要求实际费用。任何实际坏金额都使该模型和整月精确金额未知，不能过滤坏值。REQUEST 是次数、不计费。
6. 不改变 Token 数量端的 PROMPT/缓存防重复规则。费用仍累加全部非 REQUEST 金额，不能把 Token 的 PROMPT fallback 规则套到金额上删账。
7. 保留月模型、日覆盖、有效计数、质量 warnings 等既有预算门禁。精确金额可用也不能绕过 warnings。没有精确原始证据的旧显示快照不能用于预算；当前后台提醒独立重新请求，不读取前端历史缓存。账户、凭据修订、月份、免打扰、通知去重不变。
8. 极小数仍是实际业务证据：日费用 `1e-400` 不能因显示下溢成零而绕过 R19 月模型覆盖。源数值校验和金额解析均拒绝 `-1e-400`，不因它浮点下溢成 `-0` 放行；合法 `-0` 不受影响。

## 新增源码回归入口

- `decimal_amount.rs`：十进制规范化、加法、比较、科学计数法、正/负零、亚分、细于 f64 的上下界、下溢非零、精度与整数溢出。
- `usage.rs`：同模型拆片、REQUEST 排除、跨原始模型缺费、坏值在任意顺序传播未知。
- `deepseek_api.rs`：既有生产数值校验仍拒绝空字符串、非法字符、NaN、Infinity、负数及超范围源金额。
- `alerts.rs`：合成完整单日当月响应，经过生产相同的 `validate_usage_entries → build_usage_result_for_period → budget_sample`，不靠 warnings 屏蔽正常边界样本。

## 必验矩阵

固定查询 2026 年 11 月、源时间 `2026-11-01T04:00:00Z`，月 total 与 1 日日记录两侧数量/费用完整。阈值通过旧 JSON `monthlyBudgetCny: 0.80` 读取，再序列化/反序列化一次。

| 原始费用 | 阈值 | 预期预算 |
| --- | --- | --- |
| `0.799999` | `0.80` | `ok, false` |
| `0.80` | `0.80` | `ok, true` |
| `0.800001` | `0.80` | `ok, true` |
| `0.10 + 0.70` | `0.80` | `ok, true`，显示合计保持原语义 |
| `0.799999 + 0.000001` | `0.80` | `ok, true` |
| `0.799999 + 0.0000001` | `0.80` | `ok, false` |
| `0.000001 + 0.000002` | `0.000003` | `ok, true` |
| `0.000001 + 0.0000019` | `0.000003` | `ok, false` |
| `0.79999999999999999999999999999999999999` | `0.80` | `ok, false`，不能把显示的 0.8 当等号 |
| `0.80000000000000000000000000000000000001` | `0.80` | `ok, true` |
| 上一极细下界再加 `0.00000000000000000000000000000000000001` | `0.80` | `ok, true` |
| 明确 `0` | `0.80` | `ok, false` |
| 精确 `1e12`（含拆片相加） | `0.80` | `ok, true` |
| `999999999999.1 + 0.3 + 0.3 + 0.3` | `0.80` | `ok, true`，显示浮点上偏也不能错拒精确上界 |
| `1000000000000.0000000001` | `0.80` | `invalid_data, false`，即使显示舍入到 1e12 |

以上金额重复验证：同一单行多个金额、同模型多个行、反序、夹入空/REQUEST 片段。另把 `0.10` 与 `0.70` 分配到 Flash 新名和旧别名、Pro 或未知模型，必须仍包含等号，原始模型身份不能丢失。拆成同日多个 day 对象，日摘要仍只一条；数量 HIT10/MISS20/RESPONSE5 加 PROMPT30 后仍为35。

失败关闭分别检查：月费用集合空、全空片段、只有 REQUEST、一个原始模型有效而另一个缺费、有效金额夹入坏值、超精度、累计溢出、日缺失/warnings 非空、仅旧显示快照无精确证据、无效预算阈值。不得用日合计补月额，不得因精度修复清空 warnings。
