**仅完成代码修改与静态检查。以下回归尚未运行，未编译、未启动应用，也未进行 Windows 验收；不能作为通过记录。**

## 修复范围

`deepseek_api.rs` 的日汇总已经根据数量端和费用端实际返回的原始模型集合建立 `count_missing_slots`。现在 `flashOtherTokens` / `proOtherTokens` 与对应的总量、缓存命中、缓存未命中和输出字段共用这份缺项证据：费用端有某个别名、数量端没有时，该槽位的未归类 Token 为 `null`，不能把其他已知别名的部分和或零展示成完整值。

这不是按槽位总量是否为 `null` 清空全部分段。来源齐全而总量加法溢出时，仍保留可安全表示的未归类 Token。原始日模型不改写，另一槽位的合法数量、明确零与已有费用也不受牵连。

## 新增 Rust 回归（待执行）

测试使用合成平台响应 JSON，经过反序列化、生产数值校验、明确 UTC+8 查询日期范围和实际日汇总；关键场景继续断言序列化后的字段，而非直接构造界面日对象。样本日期为 `2026-11-01`，查询源时间为 `2026-11-01T04:00:00Z`。

- `r26_同槽别名只有费用_other未知且保留原始模型兄弟槽与费用`：三个 Flash 别名两两互换；A 图片 Token 为 7 或 0，B 缺数量但费用为 2 或明确 0。Flash 的 other 以及其余计数均未知，Pro 的 11 与明细零保留。A 的原始计数、B 的未知计数、各自费用与日/月费用仍保留。费用零不能代替数量零。
- `r26_别名明确数量零_other保留七或真实零`：B 有完整明确零数量，A 的 other=7 保留；A、B 都为零时保留真实 0。原始 B 的零和零费用保留，完整数据不产生缺项警告。
- `r26_flash与pro缺数量互换_other只污染缺项槽位`：分别让 Flash 或 Pro 只出现在费用端；缺项槽位 other 未知，合法兄弟槽位的 7 / 0、原始模型与费用保留。
- `r26_槽位总量溢出但来源齐全_保留安全other与费用`：Flash / Pro 的分段总和超出 JS 安全整数时，合法 other=7 / 0 保留；两个原始 Flash 别名单独合法、仅槽位求和溢出时同样保留 other=7。
